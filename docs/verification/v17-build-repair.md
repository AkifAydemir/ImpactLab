# v17 extraction and build-repair phase
ImpactLab v17 begins the executed-repository phase. The canonical repository is reconstructed only from the Current Canonical Source Snapshot and its path/byte/SHA-256 manifest is verified before any repair is accepted.
The development container used for the first v17 pass did not contain a .NET SDK and could not download one because outbound SDK download/DNS access was unavailable. That condition is recorded as an environment-blocked build attempt, not as passing or failing build evidence.
Before canonical synchronization, the extracted repository is nevertheless subjected to static compile-readiness checks. Repairs in this pass include stale continuum/backend contracts, duplicate continuum settings, removed namespace/type references, source syntax/constructor defects, extractor section-7 semantics, source-body line-break preservation, solution/project topology, and deterministic verification entrypoints.
`eng/verify.ps1` is the canonical Windows verification entrypoint. CI uses a .NET 8 SDK on `windows-latest` and performs restore, Release solution build, and the xUnit test project. Successful CI or local execution must still be recorded back into the canonical DOCX before it counts as project evidence.
