# v20 portable artifact and migration integrity verification

ImpactLab v20 extends the SDK-independent verification surface without changing numerical/product behavior. `eng/artifact_integrity.py` uses only the Python standard library and intentionally does **not** execute C# migrations, regenerate reports, compile the solution, run xUnit, or claim persistence/runtime correctness.

The portable audit verifies five evidence classes that are meaningful before the .NET toolchain is available: (1) the deterministic v15 report-golden package files match their manifest byte counts and SHA-256 values and agree on backend/timestamp identity, (2) every path referenced by the v15/v16 source-coverage matrices exists inside the canonical repository, (3) the scenario/experiment/workspace migration fixture lineage contains the expected schema versions 2, 3, 4 and 5 with matching document identity, (4) document migration sources/registry/matrix cover each 3->4 and 4->5 edge exactly once, and (5) the v10 persistence-envelope registry exposes the expected five unique migration edges through schema v3.

`.github/workflows/verify.yml` runs this audit after `eng/source_integrity.py` and before .NET setup/build/test. Its runtime evidence is written to `artifacts/verification/artifact-integrity.json` and uploaded with the other verification artifacts; `artifacts/` remains noncanonical runtime output.

The first v20 audit exposed one real re-host integrity defect: `samples/v15/report-golden/manifest.json` still carried pre-re-host byte/SHA metadata while the four report artifact payloads in the current editable snapshot had different canonical bytes. v20 updates only that manifest metadata to the current canonical report payloads; the report files themselves are unchanged, and this repair is not presented as report-renderer execution.

Executed v20 development evidence: the final canonical candidate passes all five portable integrity classes. Three temporary negative repositories were also rejected with exit 2: a corrupted report-golden payload that no longer matched manifest SHA/bytes, a migration fixture whose `schemaVersion` was changed to the wrong value, and a source-coverage matrix path redirected to a missing file. These negative repositories are runtime evidence only and are not Current Canonical Source Snapshot content.

This milestone proves canonical fixture/package/source-declaration integrity only. It does not prove that C# migrations execute correctly, serializers round-trip malformed/historical inputs, report renderers reproduce the golden package, or any build/test/runtime/numerical/security/accessibility release gate passes. Those executable gates remain open until an appropriate .NET/runtime environment is available.
