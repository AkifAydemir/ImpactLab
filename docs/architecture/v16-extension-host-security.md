# v16 authenticated extension host
Third-party extension execution now has two explicit modes. First-party packages may be loaded in-process only when the trust planner returns `TrustedInProcess`; every other package is planned for the separate `ImpactLab.ExtensionHost` executable.
The parent creates a 256-bit per-session key and bootstraps it through the redirected private stdin pipe. Every subsequent message is a versioned JSON envelope authenticated with HMAC-SHA256 over identity, correlation id, timestamp, nonce, message kind, capability and payload hash. Verification uses fixed-time MAC comparison, bounded clock skew, nonce replay rejection and an explicit `IpcAuthorizationPolicy`.
On Windows the default isolation provider attaches the child to a Job Object with kill-on-close and optional process-memory limits. On other platforms the portable provider preserves process separation but explicitly does **not** claim a restricted token/container sandbox. v16 therefore improves defense-in-depth without overstating OS sandbox guarantees.
